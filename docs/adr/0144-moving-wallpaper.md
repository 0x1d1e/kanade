# 144. A moving wallpaper is drawn by the shell, over awww's still

Status: accepted. The first slice of "Wallpaper owned by the shell" in `TODO.md`, which parked video, iris transitions from the Island and shader transitions: this one draws animated GIF and APNG files and leaves those out. Builds on [ADR 0064](0064-per-monitor-wallpaper.md) (which output shows what), [ADR 0024](0024-glass-on-every-surface.md) (the lock screen reads the wallpaper's file), [ADR 0039](0039-wallpaper-palettes-through-matugen.md) (the palette follows awww) and [ADR 0028](0028-the-runtime-is-ported-from-amane.md) (the runtime owns the Wayland seam).

## Context

`awww img` decodes a file and draws the first picture of it; an animated GIF or APNG then stands still. A moving desktop wallpaper is what the shells Kanade learns from offer, and Kanade has what drawing one needs: its own runtime with a layer window per output, a GPU image path, and Services that already say when the session is locked, when niri's overview is open and when a fullscreen window covers an output.

The tempting shape is a renderer of its own for every wallpaper: mpvpaper with a private process, or a screenshot loop. Both cost a process per output and per-frame encodes; neither is Kanade's.

The other tempting shape is a window that replaces awww. Then the palette (Matugen, ADR 0039), the wallpaper hooks, `awww query` and the lock screen's backdrop (ADR 0024, which reads the file awww says it shows) all lose the file they were reading, and `awww set` outside Kanade stops matching what is on screen.

## Decision

- **Only a moving file, only while its key is on.** `wallpaper.moving` (Settings' Wallpaper page, off by default) turns the drawing on. Off, nothing changes: awww decodes and draws every file, animated or not, and an animated one shows as its first picture. On, a file that is animated is drawn by Kanade; a still file still goes through awww exactly as before, so the static path, the hooks, the palette and the lock screen's reading of the file are untouched.
- **The file is judged by its bytes.** The first bytes say a GIF or a PNG; an APNG is one whose own animation control chunk (`acTL`) says two pictures or more, which covers a png of one picture with that chunk. The name, and so the extension, is never read. Anything else is a still.
- **Bounds before decoding.** A file over 64 MiB, or one with over 3000 pictures, is refused and stays with awww, as a file that is not animated does. The count comes from the file's own blocks, not from decoding them.
- **awww keeps its picture; the shell paints over it.** Kanade asks awww for the file as it always did, then draws its own window per output on `Layer::Background` with the namespace `kanade-wallpaper`, `WindowSize::Full`, no keyboard and no input region. awww's still is what shows while the file is read, while it pauses, in an output with nothing set and after a decode failure, so every fallback is the picture the user already had and no state has to be put back. awww's cache, `awww query`, the palette and the lock screen's backdrop keep the one file they know.
  - niri orders layer surfaces of one layer by when they mapped, and a hidden window here maps again each time a file starts, so the frames are over awww's still. A window that unmaps and never maps again would leave awww's picture alone, which is what a still wallpaper wants.
- **Decoded off the draw thread, one picture at a time.** The file is read once into memory (bounded by the 64 MiB cap) and a thread of its own decodes it into a ring of at most three pictures; a fourth waits for the pacing to take one, so a long animation costs no more memory than a short one and no decode runs on a draw thread. Each picture is composited on the file's own canvas as its GIF disposal or APNG frame control says (keep, restore, clear; over or replace), and handed to the runtime's image path as plain RGBA: no encode, no file, no second process.
- **Its own delays.** A picture stays for its file's own delay (GIF in hundredths of a second, APNG as its numerator over its denominator, 1/100 when it says none), never under 20 ms, and one that says 0 or less than that shows for 100 ms as a browser shows it. Delays count from the last due time rather than from the last draw, so a late picture does not push every one after it later. When the file ends it starts again from its first picture: a wallpaper loops.
- **Paused, not stopped.** No picture is drawn while the session is locked, while niri's overview is open, or over an output a fullscreen window covers, and the picture on screen stays. These are Services the shell already follows (`Niri`, `Toplevels`, the fullscreen set), so nothing here polls: a change of any of them wakes the pacing, which looks again and either draws or waits. The lock is read where it decides (`lock::holds`), as no Service carries it, and the lock's own state change wakes the pacing. A paused wallpaper draws no frame at all, and an idle one that has nothing to advance wakes nothing.
- **One window per output, one part each.** Each output's window reads the part named by its output, so a picture draws only the windows it is set on; a file set on all outputs hands the same pixels to all of them, one shared copy (a `Bitmap` the runtime draws without copying), whichever output it is.
- **A failure is one sentence, never a path.** A file that is refused or cannot be decoded hides every window, leaves awww's picture on screen, and says so once on stderr: no pixel, no path, no notice on the Island (ADR 0019). The shell never crashes for a wallpaper.
- **The pure-Rust `gif` crate.** GIF decoding is `gif`'s (already in the tree through the runtime's own decoding of a gif for the palette), APNG's is `png`'s frame API, which the root crate already had. No new Wayland connection: the runtime's owns it.

## Consequences

- A moving wallpaper costs one thread and up to three pictures of memory (whole output sized, plain RGBA), and one draw wake per picture of the file while it advances: a 60 fps file on a 4K output is about 33 MB of rings and a draw per 16 ms. A still wallpaper and a paused one cost nothing.
- Only GIF and APNG move. Video (mpvpaper's ground), a shader and an iris transition from the Island are not in this slice.
- The picture is drawn 1:1 to the output with `Fit::Cover`, so a file whose size differs from the output is cropped by the GPU; there is no per-output crop or fit setting.
- The window is on the Background layer, so a compositor that does not order layer surfaces by map time could draw awww's still over it; the mitigation is that the window only maps when it has a picture and maps again on each wallpaper change. A compositor doing something else would need the runtime to place the window itself.
- awww still decodes the animated file once to show its first picture, so starting one costs awww's decode plus Kanade's.
- **Not run live**: the Background window over awww's still and under every window; the first picture over awww's; a picture advancing at the file's delay; the pause in the overview, on lock and under a fullscreen window; unplug and replug; two outputs with different files; the fallback on a truncated file; the idle wake count while paused (unit-tested: the bytes' kind, the caps, the disposals and blends, the delays' arithmetic, the pause predicate; E2E NOT RUN).
