# 146. Polkit authentication on the Island

Status: accepted. Supersedes the refusal of polkit's prompts that ADR 0011 assumed and `docs/archived/design.md` stated ("Session ... not interactive, so polkit never asks for a password"; "polkit credentials stay external"). ADR 0120 stands: no privileged helper, no polkit action.

## Context

polkit asks an authentication agent for a password when a program requests an action it does not hold: mount, a package, a firewall rule, a network change from a program running unprivileged. ADR 0011 and the archived design assumed the shell never answers, so such a request went nowhere.

A prompt is outside text and a password at once. What polkit and PAM say is not Kanade's writing, and must not be trusted with the screen; what the user types must not be held anywhere after it is used.

## Decision

- **Kanade registers a user-session `org.freedesktop.PolicyKit1.AuthenticationAgent` on the system bus**, at `/org/kanade/polkit/agent`, for this logind session: it registers when its method subscription attaches, retrying with a growing wait until polkitd takes it, and again whenever `org.freedesktop.PolicyKit1` gets a new owner. Registration is serialized and cached by bus generation and polkitd's unique name, so one polkitd never gets a second agent for this session from Kanade.
- **Only the current owner of `org.freedesktop.PolicyKit1` (polkitd) may call Begin/CancelAuthentication on it.** Anything else is dropped silently: anyone on the bus can name the agent's path.
- **Only this session's own logind user is accepted as the authenticatee.** polkit's `(sa{sv})` identity is read as a `unix-user` uid and compared with logind's `Session.User` for this session; a session, a group, or another user's uid is none.
- **The password goes to polkit's stock helper**, socket-activated at `/run/polkit/agent-helper.socket`: `<user>`, then `<cookie>`, a line each, then a line per PAM message (`PAM_PROMPT_*`, `PAM_ERROR_MSG`, `PAM_TEXT_INFO`, `g_strescape`d) until `SUCCESS` or `FAILURE`. PAM runs as root in the helper, so Kanade holds no privilege, registers no polkit action, and never calls `AuthenticationAgentResponse`.
- **Refusals are quiet void replies**, which polkit reads as not authorized: nothing shows and nothing queues. That is a locked session, a missing helper socket, no unix-user identity matching this session, or four requests already waiting. A malformed call, with no cookie, is instead a D-Bus `InvalidArgs` error.
- **Three tries per request**, then it is answered as not authorized. A failed try empties the field and says how many tries are left. A request is given up on when the session locks, when the user closes the prompt, or after 30 minutes with nothing typed. Lock onset synchronously invalidates helper attempts, shuts down their sockets and clears the field before marking the lock pending or asking the compositor; it shares Auth's guard with input mutations and password writes, acquired before the lock's request mutex.
- **`Surface::Auth` holds the keyboard while it shows**, and nothing but its own answer, its own Cancel or the session lock closes it. Escape cancels and answers polkit nothing.
- **The password is typed only on the Island, only while unlocked, in a field held as `Zeroizing`/`Secret`.** It is zeroized when let go, never logged, never sent over Kanade's own socket, never persisted. It is held to 256 characters, and a control character can never be typed.
- **Auth has its own 440 × 304 shape**, with fixed request, account, password, status and action lanes in Empty, Typing, Checking and Failure. It uses the configured typography and Island theme roles. The request summary wraps to two lines and elides; `Password for <user>` names only the authenticatee, never a guessed requester.
- **Authenticate is disabled visually and behaviorally with an empty password or while checking.** Checking shows `Verifying password…` with a small spinner (static under reduced motion), hides the secret and caret, and leaves Cancel and Escape operable. Retry clears the secret and returns keyboard focus to the password; Authenticate stays unavailable until new input. Generic helper `FAILURE` says `Authentication failed.`: the protocol cannot establish an incorrect password or PAM lockout. The remaining tries are this request's budget.
- **The password's single border marks failure with the critical role; actual keyboard focus thickens that border and shows the caret.** Tab/Shift+Tab and arrows reach the password, enabled actions and Details. Space types in the password and presses focused controls elsewhere. The runtime publishes real Caps Lock state from its existing Wayland modifier events; the warning appears only while active and input is available.
- **Details is a bounded disclosure within the same shape**, replacing the request/field/status area while actions stay in place. It shows the sanitized actual full request and action ID from `BeginAuthentication`, bounded to 4096 and 512 characters respectively (an overlong value ends in an ellipsis); no details map, command inference or cookie is exposed. Controls, bidi formatting and invisible formatting characters become spaces. Oversized tokens wrap within the disclosure. Tab reaches its scroll region, Up/Down, Page Up/Down, Home/End and Space scroll, and Back returns to input. Escape always cancels the request, including in Details. Metadata is semantic content, redacted by default, and an action ID does not verify an app's identity.
- **`Bus::try_call` tells a failed call from its answer**; registration needs the reason it was refused.
- **The field component was taken out of the Wi-Fi prompt and shared** (`surfaces/password.rs`).

## Consequences

- The `polkit` Module is on unless turned off, needs only the core, and registers on start. Placement originally read niri's focused output, so Auth did not open under Umbriel. ADR 0147 extends placement to the selected compositor's shared Island focus; a never-shown prompt waits without taking input while focus is missing or overview is active, then retries on an Island change. On implementation `cc0ea5c`, live Umbriel registration, visible focused-output placement, exclusive keyboard ownership, Cancel/Escape and overview deferral/retry passed. A separate `pkcheck` exit 0 with no observed prompt or password entry establishes authorization only. Live password/PAM authentication, lock cancellation/password clearing, missing or stale focus, and niri acceptance remain **NOT RUN**. ADR 0147 records the exact binary and evidence.
- Registration is refused while another polkit agent holds this session, and stderr says why. The attached subscription retries with backoff from 250 ms to at most 30 s between attempts. Stop the competing agent and wait for registration; a shell restart is not required. A successful registration logs `kanade: polkit agent registered for this session` once per new bus generation or polkitd owner. The shipped niri config and installer add no external agent.
- **The `BeginAuthentication` argument layout, the identity array and the user name are verified** against polkit 128 on 2026-10-30 by a real request that ended in a granted authorization.
- Nothing waits on the Island forever: three tries, the session lock, a closed prompt, or 30 minutes with nothing typed each end a request as not authorized.
