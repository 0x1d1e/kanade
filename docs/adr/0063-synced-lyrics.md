# 63. Synced lyrics

Status: accepted. Extends the Media Surface (ADR 0044's follower) and the media follower's position tick; follows the subscriptions' fetching shape (ADR 0062).

## Context

The Media Surface shows what plays, not what is sung. Time-synced lyrics (LRC) exist as `.lrc` files beside a library's tracks and as a free public database, LRCLIB, that answers `GET /api/get` for a track's title, artist, album and length.

The second source is the first thing in the Media Module that leaves the machine with what the user plays. A track title and artist are personal data: they show taste, and with a time and an IP they show a day. Nothing else Kanade sends says that much (weather sends coordinates the user typed, calendar feeds send nothing of the user's).

## Decision

- **Setting and privacy.** `media.lyrics` is `off` (default), `local` or `lrclib`. `off` reads no file and sends nothing. `local` reads a file on this machine and sends nothing. Only `lrclib` leaves the machine, and only the user who sets it says so. Settings, the config reference and `kanade status` name it as asking the internet; the docs state what is sent. There is no Module switch beyond the setting, since the lookup is a part of Media, not a feature of its own.
- **What is sent, and when.** One `GET https://lrclib.net/api/get` with `track_name`, `artist_name`, `album_name` and `duration` (seconds), `Accept: application/json` and the `User-Agent` `Kanade/<version>`. No cookie, no account, no identifier. LRCLIB asks a client to name itself with an app name, a version and a link or contact; Kanade sends the name and version only, so nothing that identifies the user goes with the track. If LRCLIB ever refuses such a client, a project link (not a user's address) is the change to make. A request is made only while a track plays, the Media Surface is open, and the setting is `lrclib`. A paused player makes none; a failed look-up's wait is kept for that track past a pause or a stop; closing the Surface forgets the lyrics. Skipping through many tracks looks up only the last. Only https is spoken, redirects included (`https_only`, at most 2).
- **Order.** A `file://` track's own `.lrc` (same path, extension replaced; a regular file, at most 256 KiB, UTF-8) comes first, for `local` and `lrclib`. Then, `lrclib` only, the cache, then the network. A track without a title, an artist or a length is never asked for.
- **Cache.** `$XDG_CACHE_HOME/kanade/lyrics` (directory 0700, files 0600, atomic writes). A file is named by the first 16 bytes of a SHA-256 of the lowercased title, artist, album and length, so its name tells nothing of the track and one song in two files shares an answer. A found answer is `.lrc`, kept until pruned. A miss is an empty `.none`, believed for 2 hours, so a song LRCLIB lacks is asked once per sitting and gets a chance when lyrics are added later. At most 200 files stay; each write drops expired misses, then the oldest answers. Answers are limited to 256 KiB. Writing may fail (the error kind is logged, nothing else) and the lookup goes on without the cache. Turning `media.lyrics` off leaves the files, as the subscriptions' do.
- **Failure.** A failed or odd answer is not cached as a miss: offline, 5xx, 429 and a body that is not JSON wait with `Backoff` (30 s doubling to 1 h), or `Retry-After` in seconds (capped at 1 h) if longer; the wait is kept for that track past a pause, a stop or a skip back, so a player that flips state cannot ask again early. It is held for one track and ends when that track resolves; switching `media.lyrics` away from `lrclib` ignores it. 404 and 400, and JSON without synced lyrics, are misses. Two requests are 500 ms apart at least. The body is read to 256 KiB, the request has 15 s.
- **Thread.** One worker thread, started when lyrics are first wanted, its queue outliving a restart (`Queue`); it sleeps on that queue and costs no wakeups when idle. Views never read the network or the disk: the media follower asks the worker (`want`, `stop`) and reads what it found (`line`), and the line travels in `Playback`'s `Deck`. The worker's result nudges the follower, which publishes at once.
- **Position.** The line is the last whose time the MPRIS position has passed, from the same timeline the Surface draws (extrapolated at the player's rate, so a seek shows the right line as soon as the player says it moved). The follower's tick also wakes at the next line's time, never sooner than 200 ms after the last, so a line changes when it is sung, not at the next second; paused (rate zero), there is no next line and nothing is scheduled. `[offset:ms]` is honored. A gap between lines (an empty text) shows nothing.
- **Where it shows.** The Media Surface's header, a third line under the artist in the artwork's accent, one line, elided. Not in the Peek: a line that changes between seconds would repost the Media Activity (its `Track` is compared whole) and wake the Arbiter every line, and a Peek has room for no more than title and artist. Putting it there takes a decision on the Arbiter's rules and is left out.
- **Logging.** The lyrics, titles, artists, albums, paths and addresses are never logged or shown in `status`. `kanade status` says only the setting and how the last look-up ended in fixed words (`found on LRCLIB`, `none found`, `offline`, `rate limited`).

## Consequences

- With `lrclib`, LRCLIB (and any network observer of the TLS connection's host name) learns the title, artist, album and length of every track played with the Surface open, and when. A user who does not want that uses `local` or `off`. The default is off.
- A track's lyrics are the database's; they may be wrong, misaligned, or for another version. Kanade does not edit them.
- Streaming players (Spotify) give no `file://` URL, so only LRCLIB can serve them, and only when their metadata is complete (an album, a length).
- LRCLIB's `/api/get` is documented as taking all four fields; an empty album is sent as empty and may be answered as a miss. Not checked against the live service from this change.
- Not done: plain (unsynced) lyrics, `/api/search` fallback, word-level (enhanced LRC) highlighting, showing lyrics in the Peek, a user-agent link, and cleaning the cache when the setting is turned off.
