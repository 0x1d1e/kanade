# Limitations

- niri only. Hyprland and Sway are not supported: focused-output routing, workspace changes and screen capture come from niri IPC.
- No screen reader support. Kanade draws with the GPU and builds no accessibility tree, so the island never registers on the AT-SPI bus and Orca cannot see it. Checked on niri with `Atspi.get_desktop(0)`: every other app is listed, Kanade is not.
- A fullscreen window covers the island, Critical Activities like low battery and a pomodoro moving on to its next phase included; only the OSD and an open Surface show over it. The island sits on the Top layer, which niri draws below fullscreen windows; maximized and windowed-fullscreen windows do not cover it. See [ADR 0006](../adr/0006-island-on-top-layer.md) and [ADR 0021](../adr/0021-the-osd-returns-to-the-island.md).
- Files dropped on a Dock icon start the app with them only when its `.desktop` `Exec` has a `%f`, `%F`, `%u` or `%U` argument of its own and no `Path`; an app that takes one file at a time starts once per file, up to 8, and otherwise nothing starts and stderr says why. Paths go as they are, not as `file://` links.
- The Launcher closes as soon as an app is pressed, so an app that fails to start says why only on stderr, as the Dock's does.
- The Launcher shows emoji only from a color emoji font that holds them as pictures (CBDT or sbix), like Noto Color Emoji or Twemoji. Kanade's text draws only outlined letters, so it draws the font's picture instead; a COLR or SVG emoji font shows none, though copying still works.
- The charge limit needs UPower 1.90 or later and a battery whose driver supports charge thresholds; elsewhere its Controls tile does not show, and it is off by default (add `charge-limit` to `controls.tiles`) and `kanade battery limit` says it is unavailable. Kanade cannot set the threshold itself: UPower uses the one already set, or its default.
- Without `pactl`, `udevadm` or `dbus-monitor`, the OSD, notification Banners and battery reads poll instead of waiting for the system to announce a change, adding up to about 23 CPU wakeups a second at idle. A backlight changed by firmware without a kernel uevent shows no brightness OSD. See [ADR 0004](../adr/0004-wake-sources-on-announcements.md).
- Without `setpriv` from util-linux, helper processes like `pactl`, `udevadm`, `dbus-monitor` and `pw-dump` still work but may survive Kanade being killed abruptly. See [ADR 0004](../adr/0004-wake-sources-on-announcements.md).
- Screen recording records video only, the focused output whole, with `wf-recorder`'s `h264_vaapi` encoder; without a working VA-API driver it fails and the island says why. niri hands out a frame only when the screen changes, so a still screen records few frames. See [ADR 0013](../adr/0013-screen-recording-with-wf-recorder.md).
- Locking before sleep waits until niri says it holds the lock, which it says once every monitor on shows a lock screen; if it does not by logind's `InhibitDelayMaxSec`, sleep comes anyway and the lock shows on resume.
- An unlock sent just before sleep is asked over: the session unlocks for a moment, then locks again before sleep is let go, unless that outlasts logind's `InhibitDelayMaxSec`. Kanade sends the unlock under the same lock as sleep's gate, so only an unlock already sent races it. See [ADR 0025](../adr/0025-the-lock-screen-over-its-own-connection.md).
- The lock screen does not type the key that wakes monitors the `idle` Module powered off. It cannot know of monitors powered off any other way (`niri msg action power-off-monitors`, niri's own idle, the lid, a resume), so there the waking key is typed. When the monitors wake with no key here, the next key is dropped once. If niri does not deliver the waking key to the lock screen, a password typed within 250 ms of waking loses its first character.
- A PAM service that asks for anything but one hidden prompt (an echoed name, a second secret) fails every check: the password answers only the first hidden prompt. PAM's text and error messages show under the field, cut to 64 characters.
- With `lock.grace` above 0, any key, click, scroll or 4 px of pointer movement on the lock screen unlocks it without a password for that many seconds, only after a lock by the `idle` Module (never `kanade lock`, a lock before sleep or one asked again after a failure). Anyone at the keyboard in that window gets in.
- Caffeine's duration does not count time the machine is suspended. An idle daemon sees it only if it honors logind idle inhibitors; hypridle does, but one started while caffeine is already on misses it until it changes. The `idle` Module reads it directly.
- The `idle` Module honors logind idle inhibitors only while it can reach logind on the system bus. Without it, only caffeine and apps' Wayland idle inhibitors hold the stages, and caffeine turned off while the user stays idle counts again only from the next input or idle. See [ADR 0047](../adr/0047-idle-in-the-shell.md).
- The clipboard history leaves out only a copy its app marks sensitive with `x-kde-passwordManagerHint`, as `wl-copy --sensitive` does. A password copied without it is kept like any other copy until removed or cleared. See [ADR 0019](../adr/0019-clipboard-sensitive-content.md).
- The privacy cluster's microphone and camera see only capture that goes through PipeWire, using `pw-dump` from the `pipewire` package. An app that opens `/dev/video*` or ALSA directly, like `ffmpeg -f v4l2`, does not show. See [ADR 0003](../adr/0003-privacy-from-pipewire-graph.md).

- The `liquid-glass` finish copies the screen around each pane through niri's `wlr-screencopy`, for each pane's reflective edge, so it costs some GPU and CPU on every frame the screen behind changes. The glass is clear, with no blur (the `blur` finish is the one the compositor blurs, see below), and the edge reflects the screen around the pane rather than bending what lies under it, so text behind a pane shows through it. Over a bright page a pane darkens a little and then turns its ink dark, by the average brightness of the screen just around it, so over a page half bright and half dark either ink may be hard to read. The lock screen stays solid. See [ADR 0052](../adr/0052-liquid-glass-finish.md) and [ADR 0054](../adr/0054-liquid-glass-refinements.md).

- The `blur` finish needs niri 26.04 or later (`ext-background-effect`); without it the panes are the opaque tinted solid, and `kanade doctor` says so. niri blurs only the wallpaper behind a layer unless your config has the layer rule in [Installation](Installation.md) (`xray false`), and calls the effect it then makes experimental. The compositor's blur has no rounded corners, so Kanade gives it rows of rects a pixel tall along each pane's outline. A Banner blurs once its fade in is over, and stops as it fades out. Its ramp follows `appearance.tone`, dark with light text or light with dark ink; there is no ink flip over a bright or dark window, the pane's fill alone keeps the text readable. See [ADR 0057](../adr/0057-blur-finish.md).
- A failed reload of niri's config (a parse error) shows on the Island for a few seconds as `niri config: Failed - run niri validate`, the failed form of a live Activity, so it needs the `live` Module on and says nothing more than that; niri's own message and `niri validate` say what is wrong. It also shows when Kanade starts or reconnects after the last load failed. See [ADR 0071](../adr/0071-failed-niri-config-as-a-failed-job.md).
- Banners show a notification's text on screencasts (a share, OBS) unless your niri config has the opt-in layer rule `block-out-from "screencast"` on `kanade-banners`, see [Installation](Installation.md). The rule covers Banners only: the Island holds the privacy dots, so the Notifications Surface, which draws on the Island, still shows on a screencast. A third-party screenshot tool is not covered by `"screencast"`. See [ADR 0070](../adr/0070-banners-out-of-screencasts.md).
- Stop sharing in Controls ends only a PipeWire screen cast (a browser or chat app sharing through the portal), through niri's `stop-cast` action, so it needs a niri that has it. niri cannot stop a `wlr-screencopy` cast, like `wf-recorder`'s, so that one has no button; stop it in its own program or the Capture Surface.

- The Settings window is a normal window, so niri tiles it. To float it, add a niri window rule: `window-rule { match app-id="kanade" title="Kanade Settings"; open-floating true; }`.
- The `audio` visualizer follows the default sink as a whole, not one player, and needs `cava` built with PulseAudio support. It is untested against a live cava in this release; without cava the synthetic bars draw. See [ADR 0056](../adr/0056-audio-visualizer-through-cava.md).
- Synced lyrics (`media.lyrics`) show on the Media Surface only, not on the Island's Peek. A streaming player gives no file, so only `lrclib` can serve it, and only when it reports an album and a length. The `lrclib` lookup is untested against the live service in this release.
